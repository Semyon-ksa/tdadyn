# tdadyn.synthetic — синтетические данные с известной топологией

Генераторы наборов данных, у которых **правильный ответ известен заранее**. Это не фМРТ
и не эксперимент: единственная ценность этих данных в том, что относительно них можно
проверить алгоритм персистентных гомологий, зная, что он обязан выдать.

Задача 5 первого этапа проекта. Данные делаются **раньше** алгоритмов (Задача 2) намеренно:
иначе валидировать было бы нечем и появился бы соблазн объявить истиной то, что выдал
алгоритм.

## Где что лежит

| Пакет | Что в нём |
|---|---|
| `tdadyn.core` | общее для всех слоёв: контракты данных, `rng_for`, разбор конфига, чтение наборов |
| `tdadyn.reference` | независимый счёт над $\mathbb{Z}/2$ без библиотек персистентности — путь B проверок |
| `tdadyn.synthetic` | генераторы, сборка, критерий значимости — то, о чём этот README |
| `tdadyn.zigzag` | зигзаг-персистентность и временные диаграммы (Задача 2) |
| `tdadyn.results` | сборка отчётных чисел Результата 2 — единственный модуль, знающий и генераторы, и алгоритм |

Зависимости односторонни: слой, производящий истину, не знает о слое, который её
потребляет. Поэтому `load_dataset`, `rng_for` и `adjacency_from_snapshot` импортируются
из `tdadyn.core`, а не из `tdadyn.synthetic`.

## Установка и сборка

```bash
python -m venv .venv && .venv/bin/pip install -e ".[dev]"
```

```bash
.venv/bin/python -m tdadyn.synthetic.build --config config.yaml
```

Собирает 38 наборов (около 13 МБ) в `data/synthetic/` и пишет `manifest.json` с sha256.
Занимает несколько секунд. Флаги: `--family` (повторяемый) — собрать только одно
семейство; `--output-root` — писать в другой каталог; `--results` — дополнительно
посчитать кривую устойчивости Результата 6 (около девяти минут, поэтому отдельным флагом).

```bash
make fast    # быстрые тесты, десяток секунд; обязана проходить без зигзаг-бэкендов
make slow    # топологические проверки, около десяти минут
make zigzag  # зигзаг: оракул и бэкенды, нужен `make install-zigzag`
```

## Задача 2: временные диаграммы

```bash
make install-zigzag                # Dionysus 2, необязательная зависимость
make results                       # артефакт Результата 2
make report-zigzag                 # отчёт: собрать, выполнить, выгрузить в HTML
```

`make results` производит `data/synthetic/results/zigzag_events.json` (около пяти минут):
барштрих-коды и метрики по 18 наборам, счётчики невидимых, цензурированных и эфемерных
баров, частота ложных срабатываний на нулевой модели с интервалом и числом испытаний, сверка
независимого оракула с бэкендом — 3192 бара, 0 расхождений. Пересборка даёт тот же
`content_sha256`; меняется только отметка времени.

**Отчётные числа производит сборка, а не тесты.** Отчёт `notebooks/zigzag_report.ipynb`
читает артефакт и ничего не вычисляет, поэтому его проза не может разойтись с ним.
`make report-zigzag` собирает ноутбук, **выполняет** его и выгружает
`notebooks/zigzag_report.html`. HTML подгружает MathJax с CDN — формулы без сети покажутся
исходным текстом, числа и таблицы от сети не зависят.

Прямые вызовы — `pytest -q`, `pytest -m slow`, `pytest -m slow_zigzag`. Зигзаг-бэкенды
необязательны: `pip install -e .` работает без них, и быстрый прогон тоже.

## Отчёт

`notebooks/report.ipynb` — отчёт о проделанной работе по сессиям S1–S9: методы, решения
на развилках, результаты и ограничения, с рисунками и таблицами. Открывается с готовым
выводом, запускать не обязательно.

```bash
.venv/bin/pip install -e ".[notebook]"
.venv/bin/python notebooks/build_report.py    # пересобрать из исходника ячеек
```

Ноутбук ничего не считает сам: он только вызывает пакет. Пересборка с исполнением
занимает около двух с половиной минут.

## Что лежит в наборах

| Семейство | Каталог | Наборов | Род истины |
|---|---|---|---|
| 1. Статические облака | `static_cloud/` | 7 | `expected_betti` — числа Бетти из таблицы |
| 2. Динамические графы | `dynamic_graph/` | 2 | `betti_curve` — кривая Бетти и лог событий |
| 3. SBM | `dynamic_graph/` | 1 | `partition` — метки сообществ и расписание |
| 3. Ряды осцилляторов | `series/` | 2 | `partition` — расписание связи |
| 4. Зашумлённые | `noisy/` | 24 | `noise_level` — механизм и уровень |
| 4. Нулевые модели | `null/` | 2 | `none` — расписания нет, лог событий пуст |

**Род истины (`truth_kind`) и раскладка (`family`) — разные вещи.** Динамическая SBM лежит
как динамический граф, а истина у неё — разбиение, и баркода среди неё нет вовсе.
Обязательность полей определяется родом истины, а не каталогом (`docs/data.md`, §4.1).

## Как прочитать набор

```python
from tdadyn.core import load_dataset

dataset = load_dataset("data/synthetic/static_cloud/circle_N400_radius1_sig0.03_coeff_field2_seed20260201")
dataset.points          # (400, 2)
dataset.ground_truth.expected_betti   # {0: 1, 1: 1, 2: 0}
```

Тип определяется по имени файла массива, а не по семейству: зашумлённое облако и
зашумлённый граф лежат в одном каталоге `noisy/`.

## Чего эти данные не делают

- **Не заменяют реальные данные.** Динамика здесь не претендует на реалистичность; ряды
  осцилляторов — аналог фМРТ по структуре связи, а не по спектру или уровню шума.
- **Не подтверждают, что набор научно осмыслен** для конкретной задачи. Тесты проверяют
  соответствие заявленной истине, и только (`docs/validation.md`, §5).
- **Не дают универсальных порогов.** Параметры `topology_check` откалиброваны на облаках
  семейства 1 и на другие типы данных не переносятся — в первую очередь на коннектомы
  Задачи 3, где нет известного $\beta_k$, относительно которого можно калиброваться.
- **Нулевые модели не утверждают отсутствие признаков.** Случайный граф честно имеет циклы;
  нулевой набор позволяет **измерить** частоту ложных срабатываний, а не заявляет ноль
  (`docs/method.md`, §4.2).

## Воспроизводимость

Имя каталога — детерминированная функция генератора, параметров и seed, поэтому один и тот
же конфиг даёт то же имя и то же содержимое. `manifest.json` хранит sha256 каждого массива
и sha256 истины; пересборка сравнивается по записям без `generated_at` и `package_version`.

Оговорка: **в пределах одной среды**. Рёсслер при $c = 5.7$ хаотичен, и смена версии scipy,
метода интегрирования или допусков уводит его ряд целиком. Это ограничение, а не дефект.
